# 存量巡检

把历史快照按今天的写作契约重判一遍，回答一个问题：没有闸门的时候，漏过去多少，后来又有多少被人改掉。

结论写在创始人仓的 `data/report/agent/corpus-patrol.md`。这里留方法本身：两个脚本，一步采集、一步汇总。

## 怎么跑

在创始人仓根执行：

```bash
python3 examples/corpus-patrol/patrol.py . --samples 12
python3 examples/corpus-patrol/report.py .
```

第一步找根下所有 git 仓，每个仓按提交数均匀抽若干次（两端必取、中间等距），各自导出成一棵树，跑 `language` 与 `docs` 两套审计，逐条写进 `data/findings.jsonl`。第二步按层与时间汇总，并对消失的术语命中回溯提交。

`data/` 下的 JSONL 与临时导出不进仓，跑之前先看一眼 `.gitignore`。

## 三档为什么分开

- 随文件消失：整篇重写、改名或删除，旧命中自动清零。这不等于有人看见并改掉。
- 在留存文件里改掉：有人动手，其中一部分是专门为这个词发起的清理。
- 今天还在：仍然背着的存量。

合成一个「改掉多少」会高估人的作用——这正是第一版数错的地方。

## 抽检的分类靠什么

对改在留存文件里的术语命中，取最近一次改动该词的提交，看信息里有没有「术语」「用词」「说法」「语用」「命名」。专门清理的提交会写清楚，改写顺带带走的不写。

这是启发式，不是事实认定。抽到的比例比绝对量可信：绝对量随抽样深度变，抽得越深，见到的旧命中越多。

## 与 `qtfounder audit --patrol` 的分工

那条命令给总数与比例，够判断闸门值不值，随时可跑。这个目录留逐条明细，用来分层、分时间看，也能换一份契约重跑对比。

两边算法一致：同一文件、同一规则算一条；文件改名或删除时，原处记为消失。
